# CLAUDE.md

Guidance for Claude Code and other coding agents working in this repository.

## Project overview

retrace is a Go proxy and CLI that records AI agent sessions (Anthropic Messages API and MCP over Streamable HTTP) into SQLite cassettes, and replays them deterministically while swapping one variable (the model or the tools). It also diffs trajectories. It is a public portfolio project, so clarity matters as much as function.

Read these before changing anything non-trivial:

- [docs/vision.md](docs/vision.md): the purpose, principles and non-goals.
- [docs/spec/core.md](docs/spec/core.md): the behavior contract and acceptance criteria (AC-xx).
- [docs/adr/](docs/adr/README.md): the architecture decisions and their rationale.

## Workflow: Spec-Driven Development

1. **Spec first.** Behavior is defined in `docs/spec/` before it is implemented. If a task requires behavior the spec does not describe, update the spec first, in its own commit, and get approval.
2. **ADR for significant decisions.** A new dependency, a cassette format change, a CLI contract change or a new protocol needs an ADR (see [ADR 0000](docs/adr/0000-record-architecture-decisions.md)). Code that contradicts an Accepted ADR must come with a superseding ADR in the same PR.
3. **Trace to acceptance criteria.** Tests that verify an acceptance criterion reference it by name, e.g. `// AC-12`. Commit messages reference the AC or ADR they implement when applicable.
4. **Phase gate.** No production code is written until phase 0 (docs) is approved by the maintainer.

## Language

- All repository content is in **English**: code, comments, docs, commit messages and CLI output.
- Conversation with the maintainer happens in Spanish.

## Go conventions

- **Layout:** `cmd/retrace/` (main, wiring only) and `internal/...` (all logic). Nothing goes in `pkg/` until there is an external consumer.
  Expected packages: `proxy`, `provider/anthropic`, `mcp`, `cassette`, `match`, `replay`, `divergence`, `diff`, `cli`.
- **Build:** `CGO_ENABLED=0` must always work ([ADR 0001](docs/adr/0001-go-single-binary.md)).
- **Dependencies:** prefer the standard library. Each new module dependency is justified in the PR, and in an ADR if it is significant.
- **Errors:** wrap with `fmt.Errorf("doing X: %w", err)`. Error messages are lowercase with no trailing punctuation. Never panic outside `main` and impossible states.
- **Context:** every I/O-bound function takes `ctx context.Context` as its first parameter.
- **Logging:** `log/slog`, to stderr, structured. Never log credentials or full payloads above `debug`.
- **Interfaces:** define them at the consumer, keep them small, and do not create one until there are two implementations or a test needs a seam. The `Provider` and `DivergenceStrategy` extension points are specified in the docs.
- **Concurrency:** the proxy hot path must never block on cassette writes beyond what the spec allows. Streaming must not be buffered (AC-03).
- **Formatting and linting:** `gofmt`/`goimports`, `go vet` and `golangci-lint` clean.
- **Comments:** document exported identifiers and non-obvious *why*. Do not narrate *what* the code does.

## Testing

- `go test ./...` must pass, with `-race`.
- Prefer table-driven tests. Use golden files under `testdata/` for canonicalization, fingerprints, diff output and `show --json`. Regenerate them with `-update`, never by hand.
- Use in-process fake upstreams (Anthropic API, MCP servers) for integration tests. Tests never call real external APIs.
- Test cassettes under `testdata/` must be generated by retrace itself and contain no real credentials or personal data.

## Commits and PRs

- **Small commits:** one logical change per commit. A spec change, an ADR and its implementation are separate commits.
- **Conventional Commits:** `feat:`, `fix:`, `docs:`, `test:`, `refactor:`, `chore:`, with an optional scope, e.g. `feat(replay): serve SSE chunks with recorded offsets`.
- The subject is imperative and at most 72 characters. The body explains *why* and references `AC-xx` or `ADR NNNN` when relevant.
- Never commit cassettes from real sessions, `.retrace/` directories or secrets.

## Code review

Reviews, human or automated, follow [docs/review-guidelines.md](docs/review-guidelines.md): grounded findings, severities, the review dimensions and the output format. When asked to review a change locally, use the same rubric. Every PR also gets an advisory review from `.github/workflows/claude-review.yml`. Comment `@claude review` on a PR to request another pass.

## Things not to do

- Do not add providers, transports or divergence strategies that are outside the MVP scope (spec §12) without an approved spec change.
- Do not make replay "helpfully" fall back to real calls. Any non-recorded response must follow [ADR 0006](docs/adr/0006-strict-divergence-default.md) and carry its `provenance`.
- Do not change the cassette schema without a migration and a `PRAGMA user_version` bump.
- Do not add observability or tracing features. That is a non-goal.
